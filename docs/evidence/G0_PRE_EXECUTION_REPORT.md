**Where evaluation rows enter selection** (the G0-01 question):

- `ModelComparator.compare` draws one split (`split_rows`), fits every model
  on its training side, and ranks every model on its evaluation side.
- `AIDataFacade.train` redraws the split with the same config, so the same
  seed produces the same rows. `AIDataFacade.evaluate` then scores the
  selected model on those evaluation rows. So after `compare_models()` →
  `select_model()` → `train()` → `evaluate()`, the reported score comes from
  the rows that chose the model. The docstring calls them rows "it did not
  learn from", which is true of fitting and false of selection.
- The external `test` frame is never scored: only `predict_test` touches it,
  with `transform` only.
- There is no tuning, no threshold search and no cross-validation in the
  package, so those leakage paths are absent rather than guarded.
